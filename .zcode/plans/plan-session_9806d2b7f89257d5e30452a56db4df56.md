# Musico Online — backend fetch pipeline v2 (post self-review)

Staged in four independent, individually testable landings, ordered by certainty. All backend-internal; no command/event signature changes; no frontend files touched; nothing committed (stays uncommitted on `feat/37-am-layout`).

## Stage A — correctness & hardening (bugs, not features)

1. **Fix the resolve-time budget** (stream.rs): the 2-attempt loop multiplies the timeout — today's "240 s" is really ~8 min worst case. Restructure: interactive play = 1 attempt + 90 s; background paths = 2 attempts × 120 s. Bounded honest failures everywhere.
2. **Sweep stale `.part`/`.ytdl` sidecars** (stream.rs): prune and usage accounting both exclude sidecars today, and the kill-on-timeout path leaks one per failed download forever (invisible to the storage UI). `prune_cache` now removes sidecars older than 24 h; usage reporting includes them so the UI sees the truth.
3. **Global yt-dlp semaphore** (stream.rs): max 2–3 concurrent yt-dlp processes across all sources (interactive, pre-resolve, warmup, batch). Today they can stack unbounded.
4. **Cover fetch hardening + redesign** (stream.rs): fetch runs concurrently with the yt-dlp download inside the resolve task (hidden under download time; before the `Playing` event, so the frontend's cache-null-forever behavior is preserved); bounded sync fallback only when still missing at `to_song_info`. Add https-only + `*.ytimg.com` host allowlist + 5 MB read cap on the thumbnail URL (response-JSON-driven fetch). Verify `cover_path()` is hash-based (no traversal via videoId).
5. **Exact stream-cache matching** (stream.rs): `starts_with(video_id)` → exact `{videoId}.` match while touching this code (empty/hostile id can currently badge or resolve the wrong file).

## Stage B — speed (high-certainty wins)

6. **Cache yt-dlp availability** (stream.rs): 10-min TTL — plays stop paying a process spawn.
7. **O(1) stream-cache index** (stream.rs): lazy `videoId → path` map; hits are a hash lookup + `exists()` re-check, misses still scan once (semantics identical). Honestly sized: a scaling-correctness change, not a headline win. Prune/clear maintain it.
8. **Transport tuning** (client.rs, Cargo.toml): 10 s connect timeout, `tcp_nodelay`, pool sizing, reqwest `http2` enabled; version refresh reuses the shared client.
9. **Client version SWR** (client.rs): serve cached version instantly on TTL lapse, background single-flight refresh (≥5 min pacing); block only on first-ever call.
10. **Normalized search cache keys** (search.rs): trim/collapse/casefold for the cache key only; sent query unchanged.

## Stage C — smoothness

11. **Radio warmup with a churn gate** (radio.rs + event_bridge.rs): while a `yt:` track plays with an empty queue **and has played ≥20 s** (skipping fast never warms), fetch + pre-resolve the next radio pick; cover pre-fetched in the same worker. Advance consumes the warm pick (cache-hit, the existing <1 s C3.2 gate); warm failure falls back to the live fetch. One warm slot; a replaced warm's download finishes naturally (bounded waste: 1 track).
12. **Catalog SWR** (catalog.rs): browse/home/genres serve stale ≤6 h with one background refresh per key; empty re-parse never overwrites good data (shape-drift self-heal). Accepted limitation: the UI sees fresh data on next navigation (no push channel).
13. **Skip dead queue entries, quietly** (event_bridge.rs): bounded ≤5 advance retries through unplayable entries; failures logged, not event-spammed; falls through to radio/shuffle. This is also the TOCTOU backstop that makes the index (7) safe — 7 and 13 land together.

## Stage D — concurrency polish (riskiest, lands last)

14. **Coalesce identical in-flight InnerTube requests** (client.rs): same URL+body joins the leader's outcome without holding a throttle slot. Specified failure semantics: waiter timeout (60 s); a timed-out waiter evicts the dead entry so a later caller can lead; panic-safe publish.
